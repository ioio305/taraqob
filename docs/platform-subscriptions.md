# اشتراكات منصات ترقّب

## النموذج

الحساب واحد، لكن الوصول إلى كل منصة مستقل:

- `spx`
- `stocks`
- `funds`

يمثل كل اشتراك نشط صفاً في `platform_subscriptions`. لذلك:

- منصة واحدة = صف واحد.
- أي منصتين = صفان.
- الشامل = ثلاثة صفوف.

لا تعتمد الباقة الشاملة على استثناء داخل الواجهة؛ إنها وصول فعلي للمنصات الثلاث،
ما يجعل الإلغاء والتغيير وإضافة منصة ثانية عمليات واضحة وقابلة للتدقيق.

## مستويات الأدوات

داخل كل منصة يبقى المستوى: `radar` أو `signal` أو `edge` أو `alpha`.
الوصول للمنصة منفصل عن مستوى الأدوات فيها.

## رحلة المستخدم

1. الزائر يبدأ من الصفحة التعريفية `/`.
2. يختار منصة عند التسجيل.
3. بعد الدخول يصل إلى `/platforms`.
4. المنصات المشمولة قابلة للدخول.
5. المنصات غير المشمولة تبقى ظاهرة بحالة معتمة ومقفلة.
6. الضغط على منصة مقفلة ينقل إلى الاشتراكات مع تحديد المنصة.

## التجربة

الحساب الجديد يحصل على سبعة أيام في المنصة التي اختارها عند التسجيل. يُحفظ
الاختيار في `auth.users.raw_user_meta_data.selected_platform`، وينشئ ترحيل
`013_platform_subscriptions.sql` صف التجربة تلقائياً.

## Stripe

يرسل Checkout قائمة المنصات داخل metadata:

```text
platforms=spx,stocks
tier=edge
billing=monthly
```

عند نجاح الدفع، يقوم webhook بعمل upsert للصفوف المختارة. وعند الإلغاء تتحول
الصفوف نفسها إلى `canceled`.

يجب إنشاء أسعار Stripe لمنصة واحدة، وأي منصتين، والشامل، مع نسخ سنوية منها.

## الحماية

- قوالب الصفحات تمنع الدخول إلى منصة غير مشمولة.
- Middleware يمنع صفحات المنصة وأهم واجهاتها البرمجية.
- الموظفون يرون المنصات الثلاث لأغراض الإدارة والدعم.
- انتهاء `current_period_end` يلغي الوصول حتى لو بقيت الحالة `active`.
